# 数据隔离改造 (多用户共享部署的核心)

原则: 隔离的最后一道防线在 repository/数据访问层, 用 SQL `WHERE owner = :user`
强制过滤, 绝不依赖页面层自觉。即使上层忘了传 owner, 也要拿不到别人数据。

## 三处贯穿 owner_ldap

### 1. 数据库层
- 存用户产出的表都加 `owner_ldap VARCHAR(64) NOT NULL`, 加 `(owner_ldap, ...)` 复合索引。
- 对存量库做幂等补列(建表后 try `ALTER TABLE ... ADD COLUMN owner_ldap`, 已存在则忽略)。
- 所有读写方法签名加 `owner_ldap` 参数:
  - 列表/详情查询: `WHERE owner_ldap = :owner`(详情还要 `AND id = :id`, 越权返回 None)
  - 写入: INSERT 带 owner; UPDATE 带 `AND owner_ldap = :owner`(越权 UPDATE 不生效)
  - 子任务表(如 runs)冗余存 owner, 便于直接按用户查

### 2. 文件存储层
- 路径按用户分桶: `<runtime>/uploads/<owner_ldap>/...`、`<runtime>/experiments/<owner_ldap>/<id>/`
- LDAP 先规整(小写, 只留字母数字 `-_.`)再做目录名, 防路径注入。
- 路径拼接收敛在 1~2 个函数里(如 `get_xxx_dir(settings, owner, id)`), 改动点最少。

### 3. 后台任务/子进程
- 若训练/导出等用 subprocess, 把 owner 作为命令行参数透传(`--owner-ldap`)。
- 子进程内所有路径拼接、DB 读写都用透传进来的 owner。

## 当前用户从哪来 (auth.py)
- 生产: nginx 鉴权后经 HTTP 头 `X-SSO-User` 透传, 应用从框架请求头读
  (Streamlit: `st.context.headers`; FastAPI: `request.headers`)。
- 本地开发: 无 nginx, 回退到环境变量(如 `APP_DEV_USER`)默认一个开发身份。
- LDAP 统一小写。提供 `current_user()`(可降级)和 `require_user()`(拿不到则中断)两个入口。
- 直接复用 assets/auth.py.template, 按框架改读 header 的那一行。

## SQLite -> MySQL
- 引入 SQLAlchemy, 用 `database_url` 环境变量切换:
  - 本地: `sqlite:///<runtime>/app.db`
  - 生产: `mysql+pymysql://user:pass@host:3306/db?charset=utf8mb4`
- DDL 写成 MySQL/SQLite 通用(JSON 用 TEXT, 时间用 VARCHAR ISO8601 或 DATETIME)。
- 连接池 pre_ping + recycle 防 MySQL 断连。

## 必加的隔离单测
- A 看不到 B 的列表; A 用 B 的 id 直接查返回 None; A 越权 update B 不生效;
  owner 统一小写; 子任务表 owner 落库。
这些 case 是隔离正确性的回归保险, 务必覆盖。

## 本地开发不破坏
- 所有改动要保证 `make run` 仍能跑: DB URL 不设时回落 SQLite, 用户回落开发身份,
  文件落 `<runtime>/uploads/<dev-user>/`, 不污染老路径。
